# First use, progressive learning and discoverability

## Diagnose

Identify whether the user cannot **start**, cannot **understand**, cannot **find** or cannot **recover**. Forced tours, large empty workspaces, hidden advanced features, unexplained vocabulary and irreversible first mistakes have distinct fixes. Observe whether users skip instructions and attempt a direct action.

## Core design

- **First value:** Land a novice on a meaningful, safe task with an obvious first action. Remove mandatory product tours unless they deliver genuinely required information.
- **Contextual education:** Put instruction next to the task or failure it supports; make help accessible later without overlay clutter.
- **Safe practice:** Starter templates, sandbox state, examples, sample data and reversible actions teach through doing. Don't pollute production data unintentionally.
- **Progressive discovery:** Reveal additional complexity as capabilities become relevant. Keep other paths accessible by search or help instead of silently hiding them forever.
- **Expert bypass:** Returning users should avoid repeated tutorials and regain state and shortcuts. Users should be able to dismiss optional help.
- **Mental model:** Use familiar domain language and existing interaction patterns. For real novelty, provide a concise model and opportunity to explore, then test first-use understanding.

## Evaluation scenarios

Observe novices unprompted: first action, time to first completed task, reliance on external docs, mistaken action and recovery. Observe returning users: access to saved work, ability to use advanced commands, absence of forced interruption. Validate keyboard and screen-reader access to tours, helper popovers and dismiss controls if they are used.

## Tradeoffs

Not every complex product needs a sparse UI; expert tools may warrant dense affordances. Disclosure of security, irreversible consequences, data use and consent must precede affected actions. Respect the user's goal rather than optimizing tutorial completion as its own KPI.
